# Design: one place per feature in the settings

Issue: [#61 Settings: a more intuitive way to switch features on and off](https://github.com/goerks/GetThingsDone/issues/61)

Mockups: [`settings-features-variants.html`](settings-features-variants.html) (open in a browser; the mockup text is German because it is reviewed in German).

## Variants

| Variant | Idea | Outcome |
|---|---|---|
| 1 · One tab per feature, switch at the top | The tab "Features" goes away. The list has two groups, "Workspace" and "Features" (Releases, Team). Both feature tabs always exist and are labelled On/Off. | **Chosen: 1.A** (PO, 2026-10-17) |
| 1.A · Off: start page | A feature that is off shows a start page with a button "Switch on …"; no settings. | **Chosen** |
| 1.B · Off: dimmed preview | The settings are shown dimmed and cannot be used. | Rejected |
| 2 · One page "Features" with expandable cards | Cards with switch, settings inside. | Rejected |
| 3 · Switch in the navigation row | Like 1, with the switch in the list. | Rejected |

The choice "sprints or releases" stays in the tab "Story map" (PO decision).
