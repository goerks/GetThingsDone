# 5. Building block view

## Level 1: system

```
┌──────────────────────── Get It Done ────────────────────────┐
│  Frontend (React, TypeScript)          src/                 │
│    UI ─▶ State ─▶ Domain                                    │
│              └──▶ Data (Repository) ─┬─▶ SqliteRepository ──┼─▶ Tauri shell (Rust)  src-tauri/
│                                      └─▶ LocalStorageRepo   │      └─▶ SQLite file
└─────────────────────────────────────────────────────────────┘
```

## Level 2: Tauri shell

| Part | Path | Responsibility |
|---|---|---|
| Entry | `src-tauri/src/main.rs`, `lib.rs` | Starts the window, registers the SQL plugin and the migrations |
| Migrations | `src-tauri/migrations/` | Schema of the SQLite database (`001_init.sql`), epic palette (`002_epic_palette.sql`), sprints and epic order (`003_sprints.sql`), configurable fields and optional epic (`004_custom_fields.sql`), default values of fields (`005_field_defaults.sql`), dates and multi select values (`006_more_field_types.sql`), releases and `stories.release_id` (`007_releases.sql`), workspace settings (`008_settings.sql`), history of the releases (`009_release_events.sql`), status values with the four defaults (`010_status_values.sql`), sprint state, start items and result (`011_sprint_states.sql`), checks and Done snapshot of stories (`012_definitions.sql`) |
| Capabilities | `src-tauri/capabilities/default.json` | Allows only the SQL commands load, select, execute and close |
| Config | `src-tauri/tauri.conf.json` | Window, bundle (NSIS, current user, four installer languages) |

## Dependency rule

`domain` depends on nothing. `state` depends on `domain` and the `Repository` interface. UI depends on `state` and `domain`. Only `createRepository` knows the concrete repositories.
